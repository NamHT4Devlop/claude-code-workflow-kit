Workflow Kit

Skill Catalog

A spec-driven software-development assistant that runs on Claude Code. It grounds itself in each repo's Knowledge Base to understand both the business and the code, then supports the whole lifecycle — understand → plan → build → review → QA → operate. Every output is written for both technical and non-technical readers, runs locally, and is protected by a git safety guard.

Where a repository carries a provenlens index (Java · Ruby · TS/JS), 27 of these skills answer "who calls what" from a resolved call graph instead of grep — and where it is absent they fall back and label the output grep-depth only, so a reader always knows which one a finding rests on. See docs/provenlens.md.

📖Understand — grasp the codebase
cwk-scanDev / TeamRead-onlyReads the whole repository once and distils it into a 16-document Knowledge Base — structure, domain, data model, flows and rules — the shared foundation every other skill quietly builds on. Business rules and core flows are given stable ids, each recorded with where it is enforced and which test covers it, so a regression test can name the rule it defends and an unprotected rule stops being invisible. The business layer is never sampled. Writes the KB, never your source.
cwk-rescanDevRead-onlyKeeps that Knowledge Base honest as the code moves on, re-reading only what actually changed (via the git diff) so the docs stay current without paying for a full rescan. Rule ids are append-only — a retired rule is marked, never renumbered — because tests and past reports cite them. Updates the KB only.
cwk-askEveryoneRead-onlyAnswers any question about the codebase in plain language, illustrates it with a fitting diagram, and drills down to the exact files, fields and endpoints — so business and engineering read from the same page.
cwk-mapDev / ArchitectRead-onlyDraws the codebase as a living, interactive graph in the browser — files, classes and routes wired together by their real imports and calls — so you can see, not guess, how everything connects.
cwk-system-mapDev / ArchitectRead-onlyPulls back to the whole microservices landscape, stitching each service's contracts and events into one cross-service map and tracing the end-to-end journeys that span them.
cwk-documentBA / PM / DevRead-onlyWrites documentation that bridges business and code, mapping each concept to the precise field, function and rule that implements it — clear to a stakeholder and an engineer in the same read.
🗂️Plan — shape the work
cwk-discoverPM / PO / BARead-onlyInterrogates a fuzzy idea with sharp, forcing questions and pushes back on weak framing, turning a vague wish into a crisp, well-scoped problem statement that's genuinely ready to plan.
cwk-planPM / PO / BARead-onlyActs as a Product Owner: breaks an Epic into features, weighs the impact on existing flows, and lays out user stories and a sprint plan — opening with a plain-language summary stakeholders can follow.
cwk-plan-reviewTech Lead / PMRead-onlyStress-tests a plan through several lenses — product, architecture, risk and developer experience — and lands on a clear proceed-or-revise verdict with concrete fixes, before a line of code is written.
cwk-user-storyPM / BA / SMRead-onlyInvestigates deeply — a typed requirement or an entire Slack thread it comprehends — then writes features and INVEST stories with acceptance criteria pinned down to the smallest testable detail.
🛠️Build & Fix — write and repair code
cwk-buildDevEdits codeCarries a feature from idea to done through a disciplined 13-step pipeline — clarify, plan, generate code, review from several angles, then prove it with tests — always respecting the architecture already in place. Writes new code and tests.
cwk-fix-bugDev / QAEdits codeMeets a bug — or a QA report — with cool method: first triages whether it's truly a code defect, then traces the real root cause and lands a minimal, surgical fix guarded by a failing-then-passing regression test.
cwk-migrateDevEdits codeChanges a shared contract — an API, a database schema, an event shape, a library version — without breaking anyone, using the expand → migrate → contract pattern with a rollback ready at every step.
cwk-simplifyDevEdits codeUntangles code so it's easier to read and change without altering what it does, one small guarded refactor at a time, with the test suite staying green from start to finish.
cwk-perfDevEdits codeOptimises on evidence rather than hunches: measures the baseline, changes the single biggest bottleneck, then measures again to prove the win in real before-and-after numbers.
cwk-observeDev / SREEdits codeMakes a service answerable in production — adds structured logs, a correlation ID that follows a request across service and queue hops, and the golden-signal metrics that let you actually see what's happening.
cwk-rails-to-springDevEdits codePorts a service — or a chosen set of GraphQL resolvers and REST APIs — onto another stack (for example Rails + GraphQL → Spring Boot), preserving the contract and business behavior endpoint by endpoint and proving each one with golden-test parity before cutover.
🔍Review & QA — verify quality
cwk-reviewDev / ReviewerRead-onlyReviews a file, branch or PR in two passes — a rigorous quality checklist and a business-consistency check against the Knowledge Base — reporting findings, and only touching code if you explicitly ask it to apply the fixes.
cwk-issuesPO / BA / SMRead-onlyCloses the gap where a good plan gets retyped into a ticket tool by hand. It reads the stories this kit already wrote and turns each one into a real tracker issue — acceptance criteria as a checklist, parents linked to children, ids preserved — on GitHub or on Jira/Linear through a connected integration. It shows you every issue before it exists, creates nothing without your word, and a second run updates what it made rather than duplicating it.
cwk-qaQARead-onlyTurns a user story into an executable test plan that deliberately covers both the new behavior and the existing flows it might disturb, with every case traced back to an acceptance criterion.
cwk-qa-integrationQARead-onlyDrives a running application through a real browser to execute the test cases end-to-end, asserting from the live UI and reporting a clear pass or fail backed by screenshots — it exercises the app, not the source.
cwk-security-auditDev / SecurityRead-onlySweeps the whole repository for vulnerabilities category by category — injection, broken access control, secrets, data exposure — grounded in the code's real entry points and its auth model.
cwk-design-reviewDesigner / FE / PMRead-onlyExamines the interface for craft and accessibility — spacing, hierarchy, responsiveness, contrast, keyboard and ARIA — catching the rough edges against the project's own design language.
cwk-prDevRead-onlyPrepares a clear, well-structured pull-request description straight from your branch, or reviews someone else's PR in two passes with a blast-radius look at everything the change touches. Never pushes or merges.
📊Ops & Docs — operate and share
cwk-splunk-reportDev / SRE / On-callRead-onlyQueries Splunk for each application's errors over a chosen window, distils the noise into a single readable table, and delivers the digest straight to the Slack channel you point it at.
cwk-driftLead / EM / ArchitectRead-onlyAnswers the question nobody owns: does the documentation still describe the software? It audits the whole repository against the Knowledge Base and past plans, and reports four kinds of drift — entries that went stale, real behavior nobody wrote down, acceptance criteria that were promised but never shipped, and architecture rules the code quietly stopped following. Every finding is verified in the source, ranked by consequence, and routed to the skill that can fix it. Read-only by default; the opt-in --fix-docs mode will refresh the stale documentation for you — after showing you exactly what it would change and backing it up — but never your source code.
cwk-runbookDev / DevOps / On-callRead-onlyA Knowledge Base explains how a system works; this writes the other document — the one you read while something is on fire. Health checks, deploy and rollback (including what a rollback will not undo), a playbook per failure the system can genuinely have, alert-to-action mapping and data recovery, all traced to real files. What only a person can know — owners, on-call, SLAs — is left as an explicit blank, because an invented escalation path is worse than none.
cwk-retroSM / EM / LeadRead-onlyReads the team's git history over a period and turns it into an honest retrospective — what shipped, what went well or hurt, and a short list of concrete actions for next time.
cwk-pdfEveryoneRead-onlyTurns a report or document — Markdown or HTML, diagrams and all — into a polished, shareable PDF ready to hand to anyone.
cwk-skillifyDevRead-onlyScaffolds a brand-new cwk-* skill from a short description, wired and documented to the kit's own conventions — it creates a new skill, not changes to your application code.

How to use

  • Slash command — in any Claude Code session, from inside the project folder: /cwk-<skill> <args> (e.g. /cwk-ask how does the payment flow work?).
  • Plain English — skills auto-activate: just describe the task (e.g. “create user stories for …”).
  • Point-and-click — the Workflow Kit UI VS Code extension gives PM/SM a sidebar of cards (no commands or terminal). It also has a 💬 Ask anything card for general, non-repo questions.
  • List everything — /cwk-help.
